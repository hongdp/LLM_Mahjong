# exp113 — 纯血线数量级规模：384×12（21M，5.3× cnn_l）net2net 热启动 vs cnn_l 同配方同局数对照

- **Date**: 2026-10-16（预注册）  **Status**: running
- **Git**: `f5b92a2`（fast trunk / compile / bf16 rollout / net2net / cnn_c384b12_v3r）
- **Env**: 纯血线（零人类数据、零外部模型）；Rust 引擎镜像自对弈；RunPod Secure（起点来自纯血最强 ckpt，按 09-01 安全分层只上 Secure）

## Purpose & Hypothesis
$200 计划把训练侧/价值侧/防守侧/目标侧全部判决完毕，T=0 单局对 bc49 的平台 ≈0.47（exp107 P 256M 窗口 0.4695）。exp101 的 2× 容量（cnn_l vs cnn_m）在任何局数上都不优于 cnn_m——但那是**从零**训练、且只 2×。没测过的是**一个数量级的参数量**在**已到平台的策略**之上能不能继续兑现。用户 10-16 选定此方向（"数量级规模"，B 档预算）。
- **H1（容量兑现）**：同配方同局数下，384×12 臂（L）比 cnn_l 臂（C）在判决窗口高 **≥ +1.0 pp**（T=0 vs bc49，配对）且 L 窗口 **≥ 0.48**。
- **H0**：L − C < +0.5 pp ⇒ 纯血 PPO 在此设定下的平台不是容量瓶颈（与 exp101 一起关闭容量轴到 5×）。
- 中间：+0.5 ～ +1.0 pp ⇒ 弱信号，按延长规则处理。

## Method
- **起点（两臂相同的策略函数）**：exp107 P `games_256000000.pt`（cnn_l_v3r，128×4，4.0M）。
  L 臂用 `scripts/net2net_widen.py` 函数保持地扩到 `cnn_c384b12_v3r`（384 通道 × 12 残差块，21.0M）：新通道输入随机、输出置零；插入的 8 个残差块末层 BN γ=β=0（恒等）；旧块位于 2/5/8/11。14,831 个真实状态上 max|logit diff| 6.1e-5、max|value diff| 5.7e-6（`tests/test_net2net_widen.py` 覆盖 float64 精确等价与新容量有梯度）。
  C 臂直接从 P 256M 续跑（cnn_l_v3r）。两臂 Adam 都重置（L 因形状变化必然重置；C 用 `--reset_optimizer` 对齐）。
- **配方（= exp107 P，只改架构）**：`--engine rust --lr 3e-5 --entropy_schedule 0:0.003 --gamma 0.995 --gae_lambda 0.95 --target_kl 0.03 --clip_eps 0.2 --batch 4096 --ppo_epochs 1 --games_per_iter 2048 --dup_k 8 --games_per_worker 1024 --amp_update --shaping --shaping_schedule 0:1.0,400000:0.0`，周期清矩 `--reset_optimizer_every 8000000`（exp107 P 的维持平台配方）。
  两臂同一套性能开关 `--fast_trunk --compile --bf16_rollout`（对照公平：流水线噪声相同）。
- **总量**：每臂 **128M 局**（256M → 384M），里程碑每 8M（264M…384M），判决窗口 = **最后 4 个里程碑（360/368/376/384M）× 2 段 seed**。
- **评测**：T=0 duplicate 2v2 vs bc49，10k 墙 × 2 段（seed0 102224000 / 102224500），配对 exp102 A 224M 基线文件；本机 4080 自动评测器（`pairdiff_eval.py`），L 臂 384×12 推理在 4080 上实测可行。窗口均值判决，单格不下结论（seed 下限：单 ckpt ±1 pp、窗口 0.24 pp）。
- **在轨**：每里程碑单局 vs bc49 两段；L 臂另记新容量利用（插入块 n2 γ 的范数、新通道输出权重范数）。

## 性能工程（发射前完成，2026-10-16，本机 4080 实测）
| 项 | 前 | 后 |
|---|---|---|
| 384×12 推理（B=1024） | fp32 26k 样本/s | bf16 + GEMM 主干 + compile **77–84k**（3×） |
| 384×12 训练步（B=4096，bf16） | cudnn eager 16.7k 样本/s | GEMM 主干 + compile **23.9k**（+43%） |
| 端到端（2048 局/迭代） | 105 局/s（rollout 6.0 s / 打包 5.1 s / 更新 8.3 s） | **207 局/s**（2.7 / 1.9 / 5.2 s） |
- GEMM 主干：Conv1d(k=3) 改写为通道在后的 [B·34, 3C]×[3C, C] GEMM，参数/ckpt 不变，float64 下与 cudnn 输出、BN 统计量、梯度逐位一致（`tests/test_fast_trunk.py`）。
- bf16 rollout 的 PPO 噪声：同状态同权重下流水线 approxKL 噪声底 旧 1.28e-3 → 新 1.38e-3（主项是 BN 训练/推理模式差，bf16 只加 1.3e-4）。

## Success Criteria（预注册）
1. **健康**：L 臂首个里程碑（264M）对 bc49 不低于 P 256M 窗口 − 1.5 pp（0.455）；KL 常态（< target）；熵不塌（> 0.15）。破线 ⇒ 排查（lr/BN）后修正重发或停。
2. **早停**：L 臂 320M（64M 局）处，L − C（两段配对、最近 2 格）≤ −1.0 pp ⇒ 停 L（容量在拖累）。
3. **主判据**（窗口 360–384M × 2 段）：L − C ≥ +1.0 pp 且 L ≥ 0.48 ⇒ H1；+0.5～+1.0 ⇒ 弱；< +0.5 ⇒ H0。
4. **延长规则**（用户 09-12）：若 L 的最后两个窗口格仍单调上升 ≥ +0.5 pp 且 L − C ≥ +0.5，报用户申请追加（不自行越上限）。
5. 加冕另行：H1 后 L 终点对现纯血最强做 T=0 头对头。
