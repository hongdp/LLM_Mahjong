# exp39（预注册，用户要求）— 延长训练的效果：斜率驱动的续训研究

- **Date**: 2026-08-24 预注册  **Status**: gated（等 exp37/38 产出一个"仍在爬升"的配置）
- **Cost**: 每段 ~$15/12h；2M 局需两段（见下"12h 限制"）

## 动机（用户 2026-08-24 提出）
今天两次遇到"预算够不够"的问题，但证据是**分裂**的：
- **正面**：b2_4ext（handset 20.1M）1.0M→2.0M 确实继续涨（T1 1017.5 → 1031.1，+14），
  说明大模型确实吃更多局数。
- **负面**：exp30（HRF）从 460k 到 962k **横盘 50 万局**（878→851）；exp36 到 1.81M 仍 ~880。
  → 说明**平台期的形状能区分"慢爬"和"卡死"**，不能一律靠加预算解决。

## 核心设计：以斜率而非终点为判据
不做"无脑加局数"，而是把**是否值得续训**变成可判定的量：

### 2026-08-25 修正：5 个点远远不够（用户提出 60 副方差问题后实测）
exp36 的 7 个 ladder 点（60 副/点）实测：范围 795–910，**残差 std ±49，
是报告标准误 ±26 的 1.9 倍**（报告值只含对局采样噪声，不含 checkpoint 间的真实策略波动）。
换算成每 20 万局的斜率分辨力：

| 点数 / 跨度 | 斜率不确定度 |
|---|---|
| 7 点 / 0.3M 局 | **±44 Elo**（等于瞎猜） |
| 20 点 / 0.8M 局 | ±9.4 |
| **40 点 / 0.8M 局** | **±6.7** |

参照系：b2_4ext 数据翻倍的真实效应仅 **+14 Elo**。所以**比较两个 ladder 点毫无意义**，
必须回归。而这不需要额外成本：watcher 每 15 分钟一点，10 小时的 run 自然有 ~40 点
（exp36 只有 7 点是因为中途才挂 watcher）。

1. **全程**挂 ladder（从第一个 milestone 起，不得中途补挂），对**全部点**做线性回归。
2. **续训门控**：斜率 > 0 且显著（>1.5σ）才续；斜率 ≈0（如 exp30/36）判"平台"，不续。
3. 续训后复测同一斜率；若转负或归零则停，记录"该配置的收敛预算"。
产出：一张"配置 → 收敛所需局数"的表，用于以后估算预算，而不是每次靠猜。

## 12h flex 限制（今天踩到的坑）
exp36 目标 2M，在 12h 上限处被自动删机，停在 1,812,480（90.6%）。
→ 超过 ~1.7M 局（@40 games/s）的实验**必须设计成两段 resume 链**：
段1 跑到 ~1.6M 存 ckpt → 新机 `--resume` 续跑。
注意 `n_upd` 不随 ckpt 恢复（warmup 会重跑），warmup 150 时影响可忽略（~4 迭代）。

## Success Criteria
1. 至少一个配置在续训后 Elo 继续显著上升 → 证实"大模型需要更多局数"。
2. 或：确认所有 HRF 配置在 ~1.5M 处斜率归零 → 证实是架构上限而非预算问题。
两者都是有价值的结论（前者指导预算，后者结束 HRF 路线）。
