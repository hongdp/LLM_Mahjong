# exp42（预注册）— 梯度步数假设:batch 4096→1024,其余不变

- **Date**: 2026-08-25  **Cost**: G4 flex ~$15(1M 局 @ ~60 games/s ≈ 4.6h)  **Status**: launching

## 假设与动机
五个"更大/更不一样"的架构全部输给 2.0M 的 cnn_m 冠军配方
(handset 1031@2×预算、Mortal 纯血 998、HRF 852-896、cnn_xl 852 vs 冠军 1052),
**无一例外**。候选解释:总梯度步数 = 总样本 ÷ batch ≈ **21,000 步,不随模型大小变化**——
大模型拿着同样的优化步数要拟合 6-12 倍的参数。若成立,"scale 无用"实为"从未给够优化步数"。

## 为什么是减 batch 而不是 ppo_epochs 或加大迭代(用户 2026-08-25 提问的结论)
- **ppo_epochs=3**:样本复用 → 后几遍 ratio 撞 clip、梯度归零;且 exp41-A 第一遍 KL 已 0.0269,
  离 target_kl=0.03 仅 10%,大概率第一遍即早停,后几遍根本不跑。
- **加大 games_per_iter**:总步数 = 总样本÷batch,**不含该参数**,总步数不变;
  且迭代内 44 次串行更新的尾部更陈旧,clip 更多,方向反了。
- **batch 4096→1024**:步数 ×4 而**每样本仍只用一次**——零额外 clipping、每步 KL 更小、
  计算量基本不变。是最不碰 PPO 稳定性的版本。

## Method
基线 = exp41-B(`mortal_full_xl_pure_m46`,纯血,纪元 5 Elo **998.3±11.0**)。
**唯一改动 `--batch 1024`**;其余逐项一致(lr 6e-5、warmup 150、恒定熵 0.01、
bf16_infer、amp_update、workers 92、wait 0、seed 42、1M 局)。

## Success Criteria
1. **主判据**:Elo > 998.3 + 22(≈2σ)→ 梯度步数假设成立,五连败的判词全部要重写,
   scale 路线复活(此时应立即用同法重测 handset/HRF)。
2. Elo ≈ 998 → 假设证伪,"步数不足"排除,五连败的解释回到架构/表示本身。
3. 机制侧写:approx_kl 曲线应比基线更低更稳(每步更新更小);若 KL 反而更高,判读需谨慎。
4. 风格:立直/副露应与 B 臂同型(门清立直),若坍塌回副露锁死则另有交互,如实记录。
