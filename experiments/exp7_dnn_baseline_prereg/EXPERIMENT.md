# exp7_dnn_baseline（预注册）

- **Date**: 2026-08-14  **Status**: pre-registered；两条训练臂已启动
- **动机**: 用户提问「LLM 和传统方法差距有多少」。此前所有强度都只相对 SFT 锚点度量（RL 相对锚点约 +1000 点），但**没有外部尺度**判断这个数值算强还是弱。传统 DNN agent 提供这把尺子。

## 设计：同一把尺子
三条 DNN 臂全部在**同一引擎、同一复式牌竞技场、对同一个 SFT 锚点**测量，与所有既有 LLM 结果直接可比。

| 臂 | 训练方式 | 对应的 LLM 侧 |
|---|---|---|
| **DNN-BC** | 行为克隆，教师 = `scripts/generate_sft_data.py` 中**完全相同的教师函数**（产出 data/sft_mahjong.jsonl 的那套） | LLM 的 SFT 锚点 |
| **DNN-BC-RL** | BC 之后自对弈 policy-gradient（settlement 奖励、γ=0.995、复式牌留一基线） | LLM 的 SFT→RL |
| **DNN-scratch** | 纯自对弈 RL，无教师 | （无对应，测「不用教师能走多远」） |

**DNN-BC vs SFT 锚点是核心对比**：同一份教师知识、同一个引擎，唯一差异是函数逼近器（1.4M 参数 CNN 读张量 vs 2B 参数 LLM 读文本）。

## 信息公平性（刻意约束）
编码器只暴露 LLM prompt 里有的信息：自家手牌/副露、四家可见牌河与副露、宝牌指示牌、点数、场风自风、剩余牌数、立直标记、最后打出的牌。**不喂引擎算的向听/受入**——prompt 里也没有。否则比的是特征工程而非 agent。（已由 `test_no_shanten_leak` 锁住。）

## 两条必须声明的不对称（不是缺陷，是事实）
1. **DNN 不可能打出非法动作**（动作头被 mask），因此永远不吃格式罚分；LLM 会。这是传统架构的真实优势，不是测量偏差。
2. **同样墙钟时间下 DNN 的对局数高几个数量级**（本地 CPU ~3.5 局/秒 vs LLM 在 A100 上 ~0.03 局/秒）。因此「同对局数」与「同墙钟」是两个完全不同的比较，训练日志同时记录 `games` 与 `wall_s`，报告须两者都给。

## Success Criteria（预注册）
1. **主判据**：DNN-BC vs SFT 锚点，≥140 副复式牌（exp5 功效分析要求），配对差分 95% CI。
   - CI 不含 0 且为正 → 传统方法在同教师下更强；为负 → LLM 更强；含 0 → 同档。
2. DNN-BC-RL vs DNN-BC：RL 是否给传统 agent 带来增益（与 LLM 侧的 ~+1000 对照）。
3. DNN-scratch vs SFT 锚点：无教师自对弈能否达到教师水平。
4. **参照系换算**：把 LLM 侧已确证的「RL 相对锚点 +1076±753」放进同一张表，给出「LLM 的 RL 增益相当于传统方法的多少」。

## 已完成的实现与验证
- 12 项编码器测试绿，含**在 6 局真实对局上逐状态验证动作索引往返无碰撞**（若碰撞，agent 会打出与它评分不同的牌）。
- 自对弈循环对齐引擎：复用 `_resolve_claims`；发现并修复「回合不推进」bug（未认领的中断窗口需 `advance_turn`/`resolve_pending_kan` 收尾，否则同一玩家一直打到手牌打空）——由 21.7 步/人/局 的合理性检查捕获。
- 点数守恒核查：非 100000 的局差额恰等于未认领立直棒×1000（已逐局验证），属引擎正确行为。
- 竞技场插件化验证：DNN 自我对弈得到「无显著差异」。
