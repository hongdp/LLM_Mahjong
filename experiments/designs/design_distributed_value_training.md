# 分布式价值训练系统设计（CPU 演员 / 数据层 / GPU 学习者），性能与可扩展性优先（2026-09-02）

> 原则：每个设计分岔都用实测数据定，不凭直觉。本文档先列**问题 + 度量 + 判据**，实验结果回填，
> 最终设计写在 §5。上一版架构（design_value_actor_learner.md）已在 exp60 第 1 轮跑通，本文在其上做系统化。

## 1. 组件与候选拓扑

```
[CPU 演员 ×N] --分片--> [数据层] --分片--> [GPU 学习者 ×1(+消融副本)]
      ^                                        |
      +------------- 模型池（gen_k.pt） <-------+
```
候选拓扑：
- **T1 单机**：演员/数据层/学习者同一台（exp60 第 1 轮：本机 4080 + 24 核）。
- **T2 同机数据层**：学习者与数据层同机（本地盘），演员在别处，分片经 GCS/rsync 汇入。
- **T3 数据层独立**：数据层 = GCS（或网络盘），演员直推、学习者直拉，两端都不落本地长期盘。
- **T4 演员带 GPU**：演员用 GPU 推理服务器（3090 secure 32 核）而非纯 CPU。

## 2. 预注册的设计问题（每题一个实测、一个判据）

| # | 问题 | 度量 | 判据 → 决定 |
|---|---|---|---|
| Q1 | 学习者 GPU 饱和点：batch 多大时 samples/s 不再涨 | 本机 4080 与云 3090：batch ∈ {512,1024,2048,4096,8192} 的 updates/s、samples/s | 取 samples/s 拐点处的 batch；lr 随 batch 线性放大 |
| Q2 | 学习者的摄入/解码是否成瓶颈 | 单核解码吞吐（步/s）；学习者迭代里 ingest 占比 | ingest > 20% 迭代时间 → 解码线程/预取 |
| Q3 | 演员每核吞吐与扫描曲线（CPU 推理） | 本机：workers ∈ {8,12,16,20,24}；云 CPU pod：按核数 | 每核局/s 平坦 → 演员横向堆核；否则找每机最优核数 |
| Q4 | CPU 演员 vs GPU 演员的 **$/局** | 3090Ti/3090 secure 演员 局/s/$ vs CPU pod 局/s/$ | 便宜者为默认演员形态 |
| Q5 | 数据层放哪：与学习者同机（本地盘）还是独立（GCS） | 分片写入/读取延迟；pod↔GCS 单分片往返时间；端到端 lag（演员写→学习者可读） | lag < 1 个学习者迭代（~30s）且带宽余量 ≥10× → GCS 独立数据层可行（T3） |
| Q6 | 演员权重更新延迟（新 gen 出现 → 演员换上）容忍度 | 演员换权重的耗时；晋级间隔 | 换权重 < 1 分片时间即可忽略 |
| Q7 | 学习者消融副本能否共享一份数据层 | 两个学习者同时拉 GCS 的带宽/费用 | 可行 → 消融在同库上并行 |

## 3. 实验记录（回填）

### 3.1 本地测量（0 元）
- **Q1 学习者饱和（4080，convformer_m_v3r_m46，Double DQN + margin，fp32 fwd）**：

  | batch | updates/s | samples/s | 显存 |
  |---|---|---|---|
  | 512 | 31.1 | 15.9k | 1.4GB |
  | 1024 | 15.6 | 16.0k | 2.8GB |
  | 2048 | 7.4 | 15.2k | 5.6GB |
  | 4096 | 3.7 | 15.2k | 11.1GB |
  | 8192 | OOM（16GB） | — | — |

  **判决：GPU 从 batch 512 起即算力饱和，samples/s 与 batch 无关**。大 batch 不买吞吐，只减少更新次数
  （对 TD 传播不利）。→ 默认 **batch 512–1024**；学习者一台 4080 级 GPU 的消耗上限 ≈ **16k 步/s**。
  推论：按有效回放比 2–4 计，一个学习者要 4–8k 步/s 的演员产出（CPU 演员 1.4k/s → 3–6 台 20 核；GPU 演员 ~5k/s → 1–2 台）。
  提速只能靠 bf16 autocast / 更小模型 / 多学习者（数据并行），而非调 batch。
- **Q1b bf16 autocast 前向**：batch 512 → 18.4k 样本/s（+15%），batch 2048 → **23.0k 样本/s（+50%）**，显存减 1/3。
  → 学习者默认开 bf16 autocast（logits 转 fp32 再算损失）；bf16 下 2048 比 512 多 25% 吞吐，取 **batch 1024–2048**。
- **Q5 本地数据层延迟**：分片 2.1MB：本地盘复制 6ms；工作站↔GCS 上传 2.5s / 下载 2.3s（家用上行）。
  工作站不能当数据层的中转（32MB 锚点当时传了 12 分钟）；pod↔GCS 带宽待云测（文档记录单流 ~250MB/s）。
- **Q3 演员扫描（本机 24 核 + 4080，convformer_m_v3r_m46，四席全收，K=8）**：

  | 演员形态 | workers | 局/s | 步/s（×~120） |
  |---|---|---|---|
  | CPU 推理 | 8 | 20 | 2.4k |
  | CPU 推理 | 16 | 26 | 3.1k |
  | CPU 推理 | 24 | 25 | 3.0k |
  | **GPU 推理服务器** | 16 | **80** | 9.6k |
  | **GPU 推理服务器** | 24 | **92** | 11k |

  **判决：CPU 演员在 8 worker 处即饱和（~25 局/s），加核无效**——瓶颈是 convformer 的 CPU 逐批推理，
  不是核数；GPU 演员 3.5×。**Q4 顺带判决：CPU pod 演员 ≈ 54 局/s/$（16 vCPU $0.48/h）vs GPU 演员
  ≈ 180 局/s/$（3090 secure $0.50/h）→ CPU pod 方案否决，不再花钱探。**
  推论：一台 GPU 演员（~10k 步/s）≈ 喂饱一台学习者（bf16 16–23k 样本/s，有效回放比 1.5–2），
  拓扑天然是 **演员:学习者 = 1:1 的 GPU 对**。
- **Q2 解码吞吐**：`read_shard` 单线程 **194k 步/s**（40 分片 1.23M 步 6.3s）；学习者每迭代摄入 ~30k 步 → <0.2s，
  **摄入/解码不是瓶颈**，无需预取线程。

### 3.2 云测量
- **Q4 输入（目录实查 2026-09-02）**：RunPod CPU pod（Secure）按 vCPU 计价——`cpu3c` 计算优化 **$0.03/vCPU·h**
  （2GB/vCPU，2–32 vCPU）、`cpu5c` $0.035、通用型 $0.04–0.046。即 32 核 CPU pod = **$0.96/h**，
  而 3090 secure 32 核**带 GPU** = $0.50/h、3090Ti community 23–28 核 = $0.27/h。
  → 每核价格上 GPU pod 反而更便宜；CPU pod 只有在"每核吞吐显著更高"或"GPU 库存告急"时才有意义。
  本地 Q3 已证 CPU 推理 8 核即饱和 → **CPU pod 演员否决，不花钱探**。
- **Q3 云端 GPU 演员（L40S secure，$0.99/h，cgroup 13 核，EPYC 9554）**：w=8/13/26 → **47 / 56 / 65 局/s**
  （2× 超订阅有效）。每美元 **66 局/s/$**，不到本机 4080 演员（92 局/s）的一台，也远低于 3090 secure 的
  预估 180 局/s/$——**演员吞吐由 CPU 核数定，L40S 的 13 核配不上它的 GPU 价格**。
  演员选型规则：**按"保证核数 / 价格"选，GPU 只要够跑推理服务器即可**（3090 secure 32 核 $0.50 是目前最优；
  库存 Low 是唯一问题——本轮两次拿到一次）。
- **3090 secure 学习者 pod 建后 8 分钟 runtime 仍空 → terminate 换 4090 secure**（$0.74/h，5 核；学习者解码
  只需 1 核，Q2 已证）。运维事实：Secure 3090 库存 Low 时可能"建成即卡"，发射脚本要带 5 分钟 runtime 死线。
- **4090 secure（US-NC-1，宿主 CUDA 12.4）同样建后 6 分钟无端口 → terminate**。今早 Secure 的 3090/4090
  两次"建成即卡"，L40S secure 两次都 <1 分钟就绪 → 学习者也改 L40S secure。**规则：pod 建后 5 分钟无端口映射
  即 terminate 换型，不等**（卡住期间照常计费）。
- **Q5 实测（演员 US-MO-1 → 学习者 US-TX-4，rsync over SSH，10s 轮询）**：单分片 2.1MB，演员写盘→学习者可读
  **lag 1–11s**（由 10s 轮询主导，传输本身 ~1s）≪ 学习者迭代 10–30s → **数据层放学习者本地盘（T2）成立**，
  跨数据中心也够用；pod 上零凭证。GCS 作独立数据层（T3）的唯一动机是多学习者跨机共享——届时用"学习者 A 本地盘 +
  其他学习者从 A rsync"同样可行，仍不需要凭证。持久化由工作站侧拉取 + GCS 镜像。
- **学习者 L40S bf16 batch 1024：29.0 更新/s = 29.7k 样本/s**（4080 fp32 16k、bf16 18–23k）；摄入 0.2–0.3s/迭代。
  演员 L40S 26 worker 52–62 局/s ≈ 6.5k 步/s → **有效回放比 ≈ 4.6，学习者饿**。按 §1 公式：一台 L40S 学习者
  配 2–3 台同级演员（或 1 台 32 核 3090）才平衡。**这就是分离架构的核心可扩展性结论：演员按核数线性堆到
  学习者消耗的 1/2–1/1，成本模型见 §4。**
