# 评分体系 v2（Rating System v2）——重设计

2026-08-30。用户指令：「重新设计一套全新的系统，不要迁就历史遗留问题；确保我们能够从多个角度，
高效而准确地知道各个模型的强度」。附带授权：**纪元 6 可以作废重做**。

本文是合同：先写死决策，再实现。v1 见 [design_elo_league.md](design_elo_league.md)（2026-08-16），
它解决的问题（公共标尺、免挑对手、训练中轨迹）依然成立，被 v2 继承。

## 一、v1 的结构性缺陷（全部有 2026-08-30 的实测支撑）

| # | 缺陷 | 证据 |
|---|---|---|
| 1 | **锚池饱和 = 算力白烧** | 半庄刻度下 78 对里 **19 对是 0-2/200 或 198-200/200 零封**（24%）。零封对的 Fisher 信息 ≈ 0，却各花 15 秒 |
| 2 | **评分与"条件"耦合** | 锚只在 T=1（标定条件）下有效。候选走 T=0 就产生系统性采样税（单局 +29 / 半庄 +52），只能永远打脚注 |
| 3 | **锚/候选两级结构** | 候选之间从不直接对局，"I vs bc49"要单开一次性头对头。两个候选的评分通过锚相关，但**直接信息缺失** |
| 4 | **计分单位混用却同名"Elo"** | exp53 的 1.8× 放大系数是"逐场符号"对"复式对符号"的跨口径比较产物；真值 ≈2.5×。**错误常数在榜上挂了一整天** |
| 5 | **原始数据不落盘** | 对局文件只存复式对聚合 diff，换口径必须重打。模块自述"any fit can be redone from primary data"从未兑现 |
| 6 | **纪元守卫不完整** | 指纹只覆盖 5 个引擎文件；`hanchan.py`（半庄规则）和 `action_space.py` 不在内。exp53 的读数被两次规则修复静默作废，无人报警 |
| 7 | **工件不持久** | 纪元 6 榜单五行 ckpt 指向另一会话的 `/tmp/claude-*/scratchpad/`，会话结束即不可复现 |
| 8 | **调度是手工的** | 每次评分手敲命令、手挑 seed0、手挑锚子集。没有"谁跟谁在什么条件下打过多少"的账 |
| 9 | **无不确定性驱动** | 决定冠军归属的那一对和早已分出胜负的那一对，花同样的 200 局 |

## 二、v2 的九条设计决策

### D1. 被评分的实体 = (checkpoint, 条件)，不是"模型"
`bc49@T0` 与 `bc49@T1` 是**两个实体**，各有评分。采样税不再是脚注，而是**被测量的量**
（两者评分之差）。缺陷 2 从根上消失。条件包含温度，未来可扩展（如 top-p、思考预算）。

### D2. 单层扁平池，取消锚/候选分级
所有实体在一张图里联合拟合。保留一个钉子（`bc_cnn@T1` = Elo 1000 / pt 0）只为跨纪元可读，
不再有"锚点特权"。缺陷 3 消失：任意两实体只要打过就有直接信息。

### D3. 只追加的对局账本，一行 = 一场（不是一对）
`experiments/rating/matches.jsonl`，每行：
`match_id, ts, driver, unit, seed, wall, seat->entity_id, seat->temperature,
per-seat {points, uma, placement}, n_deals, busted, fingerprints{engine, hanchan, action_space}`。
**实体 id = checkpoint 内容的 sha256 前 12 位**——改名/移动不会静默改变身份（缺陷 7）。
账本不可变，一切派生。缺陷 5 消失。

### D4. 指纹过滤取代"纪元作废"
拟合时按当前指纹集**筛选**行，而不是把历史一笔勾销。旧行留在账本里，只是不被选中。
跨纪元比较从"禁止"变成"可证伪的经验问题"——就像今天实测出"半庄规则修复对强度读数影响≈0"。
缺陷 6 消失，且纪元切换不再是破坏性操作。

### D5. 四实体同桌 + 循环轮转复式
一桌坐 **4 个不同实体**，一场产出**一个完整顺位**（等价 6 个两两对比），而 2v2 只产出 1 个。
同一牌山序列打 **4 次循环轮转**，每个实体在每个座位各坐一次，席位/亲位运气基本抵消。
底层已具备：向量化 worker 的 `league_plan` 本就支持逐席位不同模型。
**信息效率预计提升 3-6×**，这是缺陷 1/9 的主要解药。

### D6. 评分 = 账本的纯函数，多视角并列
一批对局，多把尺子，**每把尺子标注单位，永不混列**：
- `elo_match`：逐场两两胜负的 Bernoulli MLE（四人桌用 Plackett-Luce 顺位似然）
- `pt`：雀魂货币 `pt = 顺位点 + (点数−返点)/1000`，**线性配对模型** `m_ij = θ_i − θ_j` 加权最小二乘
- `placement`：首位率 / 四位率 / 平均顺位（带 CI）
- `h2h`：两两矩阵 + 精确 CI
- 复式聚合（`sign_pair`）作为**方差缩减的拟合选项**，不是另一个目标量
每个表都可离线重拟合，不用重打一局。缺陷 4 消失。

### D7. 信息驱动的排程
- 每对的 Fisher 信息 ∝ `p(1−p)`；结合驱动的**实测吞吐**（向量化 967 半庄/分、batch-1 27/分、
  Mortal 桥 6.7/分）算**单位时间信息增益**，贪心分配预算。
- 目标可声明：既可以是"每个实体的自身 SE ≤ X"，也可以是指定对比（"冠军 vs Mortal"）。
- 连通性硬约束：每个实体至少 3 个 |Δ|<250 的对手，且与钉子实体连通；防止图裂开。
- 停止规则：目标 SE 达成即停，不是"每对 200 局"。

### D8. 注册表与持久工件
`experiments/rating/registry.json` + `experiments/_registry/<id>.pt`。注册时**拷贝**
checkpoint 并记录 provenance（run 目录、git commit、arch、动作空间、编码器、参数量、谱系）。
未注册的 checkpoint 不能进对局。缺陷 7 消失。

### D9. 成本核算入账
每个驱动上报实测 matches/min，写进账本行。排程器用**实测**吞吐而非猜测；报告里给出
"本次刻度花了多少 GPU 分钟"。

## 三、保留的 v1 资产
向量化 GPU 竞技场（36×）、复式配对思想、sign-MLE 拟合器、引擎指纹机制、半庄状态机
（连庄/本场/供托/流满/击飞/uma）、Mortal mjai 桥 + 分片并行、探针族（defense_iq / 风格剖面）。

## 四、纪元 7 = v2 的首个刻度
纪元 6 作废（它自己的议程也只交付了一半）。纪元 7 用 v2 重打，
主表 = **半庄 × 全 T=0（部署形态）**，副表 = pt 榜、顺位榜、单局榜、T=1 切片。
Mortal 作为外部参照实体入池（原生贪心，只与够得着的实体对局）。

## 五、实现顺序
1. `src/eval/registry.py`、`ledger.py`（D3/D8）——账本与注册表，含从现有对局文件的导入器
2. `src/eval/fits.py`（D6）——三种拟合 + h2h + 顺位表
3. `src/eval/arena.py`（D5）——四实体同桌 + 循环轮转，复用向量化 worker
4. `src/eval/schedule.py`（D7）——信息/秒 贪心排程 + 连通性约束
5. `scripts/rating.py`——CLI：`register / schedule / play / fit / board`
6. 纪元 7 重打 + 台账订正

## 六、验收判据（预注册）
- **导入无损**：现有 exp56 对局导入账本后，用 `fits` 重算出的 sign_pair Elo 与当场拟合值
  逐项差 < 0.5 Elo（否则拟合器有 bug）；
- **四人桌增益实测**：同样 GPU 分钟数下，四实体桌相对 2v2 的平均评分 SE 降幅 ≥ 1.5×
  （若不达标，D5 退回 2v2，并把结论记进 FINDINGS）；
- **排程增益实测**：信息驱动排程达到"全员 SE ≤ 15"所需 GPU 分钟 ≤ 等量均分排程的 60%；
- **可重拟合**：删掉所有派生表后，仅凭 `matches.jsonl` 能重建全部榜单，逐项一致。
