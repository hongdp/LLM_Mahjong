## 1. 结论摘要：按影响排序的不一致

两套引擎**在规则逻辑上没有发现互相不一致**（1500 局逐步对拍通过，hanchan 驱动是 1:1 移植）。下面每条不一致都是**两边同时存在**。

| 排名 | 项目 | 雀魂 | 我们（Py 和 Rust 相同） | 频率 × 点数影响 | 影响面 |
|---|---|---|---|---|---|
| 1 | **西入/南入 + 和了止め/听牌止め**（§2 #13 #14） | 南4结束时一位 <30000 进西场（东风战进南场），延长场打到有人 ≥30000 就结束，不再进第二个延长场。All Last 时庄家为一位且 ≥30000：和了或听牌都**强制终局**（S1 S2 S3 S6 S8） | `hanchan.py:200-211` / `hanchan.rs:113-128`：南4庄家一下庄就终局，不看 30000；没有西入；All Last 庄家一位照样连庄 | 估：庄家一位碰上止め的局面约占 5–10% 半庄；西入约占几个百分点。不改点数结算，但改变 All Last 的顺位决策与终局分布 | 只影响半庄训练和评测（`play_hanchan_gen`、VecEnv hanchan、`run_hanchan_arena`）；单局随机场况模式不受影响 |

另有几处**规则细节没查到、引擎可能偏严或偏宽**（CANNOT TELL），见 §3：立直后暗杠的面子构成条件、明杠后岭上开花算不算新杠宝、包牌复合役满的分摊方式、牌山不足 4 张能否立直。

**非规则、但与"按雀魂打"相关**（只记录，不判引擎错）：
- 段位 pt 与 uma 不同。引擎的 uma 是 +15/+5/−5/−15，与雀魂结算界面显示的分数一致（S1 S2）。但段位 pt 用房间特定的顺位点，严重不对称，例如玉之间半庄 +125/+60/−5/−180、王座之间 +135/+65/−5/−225（S2）。训练目标没有体现"四位重罚"。
- 单局随机场况模式（`randomize_round=True`）没有本场，Rust `t.honba=0`，Python 没有这个属性。这是已知设计。
- Python 评测路径 `play_hanchan`（`hanchan.py:231-243`）没有给 table 设 `honba`，v3rh 编码器 `encoder.py:406` 会读到 0。Rust 的 `new_hanchan` 会设置真实本场。这是观测上的不一致，不是规则问题，只影响 `run_hanchan_arena` / `rate_mortal_hanchan` 这类 Python 半庄评测里的 v3rh 模型。
