# exp12_plateau_breaker（预注册）

- **Date**: 2026-08-16  **Status**: pre-registered → 启动
- **问题（用户）**: PPO 为何总在一定程度后进入平台？是 policy 变快 value 跟不上，还是 optimizer momentum 固化？
- **已有证据排除/修正**: value-lag 不成立（critic EV 仅 0.02-0.10，且无 critic 的 REINFORCE 同样出现缓坡）；
  Adam「固化」修正为反面——信号萎缩下恒定 lr 的步长相对偏大，噪声游走呈现为平台。
- **主因候选**: ①熵奖励均衡（系数恒 0.03，末段 pg_loss 仅 +0.0005~0.003，熵稳在 1.1-1.2 不再降）；
  ②优势噪声地板（回报 90%+ 不可约噪声，动作价值差随强度收窄，SNR 由批量决定）；③lr 未退火。

## 设计（单变量 ×3，全部从 exp9 的 600k checkpoint 续训 ~100k 局）
| 臂 | 唯一改动 | 若为主因的预测 |
|---|---|---|
| E | entropy_coef 0.03 → **0.01** | win 恢复上行，熵继续下降 |
| B | games_per_iter 2048 → **8192**（4× 批量） | win 恢复上行，熵不变 |
| L | lr 1e-4 → **3e-5** | win 小幅上行，曲线更平滑 |
其余与 exp9 逐项相同（ppo_epochs 1、MC 优势、dup_k 8、drop_zero、seed 42）。

## 判据（预注册）
1. 训练侧: 各臂末 20k 局的 win_rate 相对 exp9 终点（66-68% 带）的变化方向与预测比对。
2. 强度侧: 各臂终点 vs exp9-600k 起点，200 副复式竞技场；显著为正 = 该机制确认参与构成平台。
3. 多臂同时为正 → 平台是多机制叠加（预期如此），按效应量排序。
