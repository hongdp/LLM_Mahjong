# exp41（预注册）— 完整对齐 Mortal 的输入/输出，用我们的优化算法从零自对弈

- **Date**: 2026-08-24  **Cost**: 2 臂 × G4 flex ~$15 = **~$30**（各 1.0M 局）
- **用户指定**：对齐 Mortal 的 feature 与 backbone、head 按我们训练需要设计；两臂都做（对照 + 纯血）。

## 科学问题
Mortal 的强度来自**架构 + 表示**，还是来自**人类牌谱训练**？把它的模型（输入表示、backbone、
动作空间）原样搬过来，只把训练换成我们的从零自对弈 PPO，看能走到哪。

## 已实现（本次三个提交）
- `mortal_obs.py`：Mortal 观测 **v3（934 平面）**的逐组移植，平面游标断言必须正好落在 934。
  **未选 v4（1012）**：v4 嵌了 Mortal 单人 EV 求解器（algo/sp.rs）的输出，移植它是另一个项目级工程，
  任何偏差都会静默污染对照；v3 保留了全部派生牌效特征（shanten / waits / furiten /
  keep-shanten / next-shanten / 无条件听牌），正是本实验关心的那部分。
- `mortal_action.py`：**46 槽**动作空间。3477 个真实决策验证全部可映射、无意外碰撞。
- `action_space.py`：可插拔适配器。native(374) 经**逐位一致性测试**证明零行为改变；
  Mortal 的两步协议（立直/杠先宣告后选牌）封装在 `follow_up()` 内，native 永远返回 None。
- 批量 rollout 与推理服务器已支持按模型的动作宽度 + 第二轮批查询。

## 两臂（唯一差异 = 派生特征）
| 臂 | arch | 输入 | 谱系 |
|---|---|---|---|
| **A 对照** | `mortal_full_xl_m46` | 934 平面，**派生牌效特征已填充** | 知识注入，**不入冠军谱系** |
| **B 纯血** | `mortal_full_xl_pure_m46` | 934 平面，**派生平面置零** | 只用规则可见的公开记录，**留在纯血谱系** |
两臂张量形状完全一致 ⇒ **A−B 的差 = "把牌效答案写进输入"值多少 Elo**。
这直接对应我们量化出的头号短板（听牌巡目 10.4 vs 人类 8–9.5、听牌率 42% vs 55–65%）。

配方：`--lr 6e-5 --warmup_updates 150`（exp37 的深栈步长结论）、恒定 `--entropy_coef 0.01`、
`--bf16_infer --amp_update`、1.0M 局、seed 42。

## Success Criteria
1. **主判据（架构+表示 vs 训练方法）**：A 臂 T1 > **1031.9**（cnn_m 冠军配方）
   ⇒ 我们此前的 scale 失败是自家架构问题，不是配方问题；Mortal 型设计在从零自对弈下可行。
2. **派生特征价值**：A − B 的 Elo 差。若 ≥ 50 ⇒ 牌效短板确实主要是输入表示造成的，
   这会直接指导纯血线要不要放宽"零派生特征"原则（需用户决定，不自动放宽）。
3. **纯血线**：B 臂 T1 > 1031.9 ⇒ 纯血谱系拿到新冠军。
4. 若 A、B 双双 ≲900（与 HRF 同区间）⇒ 判**问题在训练配方而非架构/表示**，
   后续重心转向配方（样本效率 / 目标函数），停止架构探索。

## 诚实声明：不能直接回答"是否达到 Mortal 水平"
我们的引擎是**雀魂单局规则 + 场况随机化**，Mortal 是**天凤半庄**。即便模型完全对齐，
两者也不在同一环境里，Elo 池里也没有 Mortal。要真做这个比较，需要走已有的 MJAI 桥
（`mjai_bridge.py`，已有 ShadowTable + 张量/合法集逐位一致测试）把 Mortal 接进我们的
Elo 池作锚点——即 docs/design_m3_human_yardstick.md 的 M3 方案，**本实验不含这一步**。
本实验回答的是"同一模型在我们的环境+从零自对弈下能到什么水平"，
"vs Mortal 本尊"留给 M3。
