## 🔴 P0 — 会直接毁掉 RL 训练（跑正式实验前必须修复）

### 1. ✅ 输家的负奖励从未进入训练数据
- **位置**：`src/tasks/mahjong/table.py`（step/step_interrupt 的和牌返回值）、`src/tasks/mahjong/orchestrator.py`（`reward=rewards[player_id]`）
- **现象**：和牌时引擎返回 `{胜者: +50, 其他三家: -10}`，但轨迹记录只取当前行动者自己的奖励，其他三家的 -10 被丢弃；对局结束后也没有把终局奖励回填到四条轨迹的逻辑。
- **后果**：放铳零惩罚、被自摸零惩罚。设计文档 4.2 节（放铳强负反馈 → 防守学习）完全无法生效。
- **修复方向**：`run_rollout` 在对局结束时，将终局奖励按玩家回填到各自轨迹的最后一步（或新增一个 terminal step）。这是管道级改动，也是后续实现放铳者付全额的前提。

### 2. ✅ Riichi 是无条件免费奖励，最优策略是每巡都立直
- **位置**：`table.py` `get_legal_actions`（无听牌校验）、`step` riichi 分支（+1.0）、`rewards.py`（riichi 再 +1.0）
- **现象**：手牌 14 张时每张牌都可宣告 riichi，不检查听牌、不锁手牌、不扣供托；引擎 +1.0、reward model 再 +1.0，合计 +2.0 —— 等于最优切牌的满分，且每巡可重复。验证 run 中已观察到「立直切 6z」的明显非听牌立直。
- **后果**：RL 梯度必然收敛到无脑立直刷分。
- **修复方向**：riichi 仅在门清且切出该牌后向听数为 0（听牌）时提供；删除两处即时 +1 奖励；立直后锁手牌（后续摸牌只能摸切或自摸）。

### 3. ✅ 副露有即时正奖励，但副露后的手永远无法和牌
- **位置**：`table.py` `step_interrupt`（pon +5 / kan +8 / chi +3）、`_is_winning_hand`（要求恰好 14 张门清手牌）、`rewards.py`（pon 再 +1）
- **现象**：副露拿即时正奖励，但副露后手牌只剩 10/11 张，`_is_winning_hand` 永远返回 False，ron/tsumo 不再被提供。
- **后果**：副露 = 白拿奖励 + 放弃和牌可能，模型会学成「见牌就碰」。
- **修复方向**：(a) 删除所有副露即时奖励（副露好坏应由终局结果决定）；(b) 副露记账改为记录副露的具体牌组，和牌校验改为「门清部分 + 副露组」联合判定（每副露一组，所需门清牌数 -3）。

### 4. ✅ 中断动作信任模型自报的 tile 属性，可以骗和
- **位置**：`table.py` `step_interrupt`：`tile = match.group(2) or last_discard`
- **现象**：ron 的和牌校验用模型提供的 tile。输出 `<action type="ron" tile="7p" />`（7p 是自己缺的牌而非实际切牌）即可 +50 白赢；pon/kan 同理可用任意手中对子「碰」任何切牌。
- **修复方向**：中断阶段一律忽略模型提供的 tile 属性，强制使用 `last_discard`。一行改动。

## 🟡 P1 — 正确性 bug

### 5. ✅ 动作提取取第一个匹配，`<think>` 内提到的动作会覆盖真实动作
- **位置**：`orchestrator.py` turn_node / interrupt_node：`re.search(r'<action\s+.*?/>', raw_output)`
- **现象**（已复现验证）：模型思考里写「可以考虑 `<action type="ron" />`，但还是跳过」、正文输出 skip 时，引擎执行的是 **ron**。
- **修复方向**：先 `re.sub(r'<think>.*?</think>', '', raw, flags=re.S)` 再提取，或取最后一个匹配。

### 6. ✅ 中断优先级按座位顺序先到先得
- **位置**：`orchestrator.py` interrupt_node 的 offset 循环
- **现象**：下家先碰，对家就失去荣和机会。真实规则：ron > pon/kan > chi。
- **修复方向**：先收集三家意向，再按优先级裁决执行。

### 7. ✅ 无 4 副露上限
- **现象**：理论上可副露 6 次把手牌打到 0 张（有空手牌保护不会崩溃，但状态荒谬）。
- **修复方向**：`get_interrupt_actions` 在 `len(fulus) >= 4` 时不再提供副露。

## 🟠 P2 — 观测（状态提示词）问题

### 8. ✅ 玩家看不到自己的牌河和副露
- **位置**：`table.py` `_format_state` 循环跳过 `i == player_id`
- **后果**：模型无法判断振听（不知道自己切过什么），副露后手牌变少却无从解释。

### 9. ✅ 状态里的全局信息全是假数据
- Dora 恒为 `3p` 且无任何实际效果；点数恒 25000；局数恒 1；供托恒 0；无剩余牌山数。

### 10. ✅ 合法动作顺序随机
- **位置**：`table.py` `get_interrupt_actions` 的 `list(set(actions))`
- **现象**：与 SFT 数据的排序约定（commit `23cdd17`）不一致，提示词不稳定。
- **修复方向**：用固定排序替代 set 去重。

### 原本未实现、现已补齐的规则

- **3.13.2 同巡振听 / 3.13.3 立直见逃永久振听**：切牌时快照 `_ron_chance`（谁能荣和这张），
  鸣牌窗口关闭时 `_apply_missed_ron` 落флаг；摸牌/鸣牌解除临时振听，立直者转为永久振听。
- **3.11 双响/三响**：`step_ron(player_ids)` 一次结算所有合法荣和者，放铳者对每家全额支付；
  供托归座次上离放铳者最近的和牌者。orchestrator/batch_rollout 共用 `_resolve_claims`。
- **4.2.1.12 抢杠**：加杠不再即时生效，`step` 返回 `info["chankan"]` 打开只允许 ron 的中断窗口；
  无人抢杠才 `resolve_pending_kan()` 补杠、翻杠宝牌、摸岭上。暗杠不开窗（RCR 仅规定加杠可抢）。
- **情境役与里宝牌**：`_situational_config` 接入一发、双立直、抢杠、岭上开花、海底捞月、
  河底捞鱼、天和、地和、人和；立直和牌时按已翻宝牌张数翻出等量里宝牌指示牌。
- **3.12 立直后暗杠**：按规则书三个条件放行（摸到第四张 / 该刻只能当刻子 / 不改变听牌）。
  条件 2 用"该牌不与手牌构成任何顺子搭子"的保守近似——可能否掉极少数合法暗杠，但绝不放行违规暗杠。
- **4.2.5.10 包牌（大三元/大四喜责任支付）**：`_record_pao` 在鸣出第三张箭牌刻子 /
  第四张风牌刻子时记录责任者；自摸由责任者全付，荣和由责任者与放铳者各半。
  （按"已亮出的副露"计数，不含暗刻——常见竞技解释。）
- **`has_double_yakuman=False`**：规则书役满表为平级，无双倍役满。

### 场数随机化（新增能力，非规则修正）

`PyMahjongTable(randomize_round=True)` 随机抽取场风（东/南）与庄家座次（0-3），
局数显示为 `{场风}{庄家+1}局`，自风随之变化。训练默认开启
（`MahjongTask` 的 `randomize_round` 配置项，默认 `True`），引擎与工具默认关闭以保证测试可复现。
**注意**：SFT 语料若在此之前生成，只见过「东1局 / 庄家0」，
建议用 `scripts/generate_sft_data.py`（`RANDOMIZE_ROUND = True`）重新生成以覆盖全部场风/自风组合。

### 🔔 未来必须补齐：多局结构

当前一个 episode = **一局**。以下 RCR 条目因此尚未实现，等进入多局/半庄训练时必须一并补上：

- **2.9 连庄与下庄**：庄家和牌或流局听牌则连庄，否则下庄；连庄棒（本场）每次 +100 点，
  和牌时每本场额外 +300 点（自摸三家均摊、荣和放铳者全付，RCR 4.3.4）。
- **2.10 场风推进**：东场打完进南场；`round_wind` 需随局数推进而非随机抽取。
- **2.11 游戏长度**：半庄（东南战）为锦标赛标准。
- **2.12 名次奖分（uma）**：起始 30000 点、终局按 (点数-30000) 排名加 +15000/+5000/-5000/-15000。
  当前的 `RANK_BONUS = [2.0, 0.5, -0.5, -2.0]`（等效 ±2000/±500）是**单局尺度的替代品**，
  多局落地时应换成真实 uma 并只在半庄结束时结算一次。
- **3.12 流局时供托留台**：跨局携带的供托/本场需要进入状态与 prompt。

### 项目决定保留的偏差（非缺陷）

- **累计役满**：13 番以上算役满（`kazoe_limit` 取库默认），RCR 4.2 为「11 翻以上三倍满」——用户决定保留。
