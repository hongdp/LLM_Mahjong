# 三项推进设计（2026-08-21，用户指令）：输入扩展 v3 / 模型 scale-up / DQN vs PG

## A. 输入扩展 v3 —— 原则：「完整的公开对局记录，零派生特征」
用户要求：减少手工特征工程，但不遗漏有效信息。执行准则：**凡是桌面上任何玩家都能看到的
原始事实，全部编码；凡是需要「麻将知识」才能算出的量（向听、受入、筋、危险度），一律不给**。
这与 AlphaZero 的「完整棋盘 + 零人类知识」同构。

现 v1 编码（15 平面 + 20 标量）的历史包袱：为与 LLM 提示词信息对等而**有意瘦身**（encoder.py
docstring）。LLM 对照已结束，该约束作废。当前**遗漏的公开事实**：
1. 牌河**顺序**（v2 的 order 平面只在 BC 下测过 null，RL 从未用过）；
2. **立直宣言牌的位置**（哪一张是宣言牌——读牌的核心公开信息）；
3. **摸切/手切**标记（引擎目前**不记录**，需加 `tsumogiri` 旗：纯公开事实，不是策略知识）；
4. 牌河中被他家鸣走的牌（display river 已弹出；furiten_river 保留——需显式标记「被鸣走」）；
5. 副露的**被鸣牌来自谁**（表征关系：谁喂了谁）；
6. 立直**时机**（第几巡宣言）与各家剩余摸牌机会、是否一发中；
7. 点数差（相对）、场风/自风（已有）、供托/本场（单副设定下恒 0，保留位以备半庄）。
（赤宝牌：本引擎按 EMA 规则无赤五，**不适用**——更正此前说法。）

编码形态：仍用 34 牌轴平面（保住卷积先验）：每家牌河 = 「顺序值平面 + 摸切平面 + 宣言牌平面 +
被鸣走平面」×4 家；副露 = 每家 chi/pon/kan 三平面 + 来源家平面；预计 ~50-60 平面 + ~30 标量。
**实验形态**：exp23 = 共享协议单变量（encoder v1 → v3），判据 Elo + defense_iq（输入补齐后
防守是否可学是核心看点）。

## B. 模型 scale-up —— 瓶颈是 CPU rollout 的 batch-1 延迟，不是 GPU
实测（本机单线程，30 workers 吞吐按 SKILLS 的 77/23 引擎/网络时间构成外推）：

| cnn 规格 | 参数 | b1 延迟 | 估计吞吐 |
|---|---|---|---|
| 64×3（现役） | 1.94M | 0.65ms | 25 局/s |
| 128×6 | 4.1M | 1.9ms | 17 局/s |
| 128×10 | 4.5M | 2.8ms | 14 局/s |
| 192×20 | 9.7M | 9.2ms | 6 局/s |
| 192×40（Mortal 级） | 14.1M[^p] | 17ms | **3.6 局/s**（700k 局 ≈ 54h） |

[^p]: **2026-08-24 更正**：14.1M 是按*我们*的 head 风格（flatten 192×34 直接进 Linear）估的。
    Mortal 真实设计在 neck 处压缩（Conv→32ch → Flatten → Linear(1088→1024)），省掉约 3.2M。
    实测同规格（`mortal_bb_xl_r`，含我们的 374 动作头）= **11.2M**，其中 40 个 block 占 9.07M（80.7%），
    与 Mortal 逐参数一致；stem 因输入平面 21 vs 1012 少 57 万。见 exp40 预注册。

结论：Mortal 级模型在现行「CPU 逐次推理」范式下不可行，**触发 SKILLS 已预定的条件
（b1 ≥10ms）→ 必须做中心化 GPU 批量推理**。路线：
1. **先做引擎优化**（SKILLS 排序提醒：引擎占 77%，对所有架构生效）——向听/合法动作缓存、
   牌河更新增量化；目标把引擎份额砍半。
2. **rollout 重构为状态机 + GPU 推理服务**：30 个 worker 只跑引擎，把观测推到共享队列，
   一个 GPU 进程凑 batch（L4 上 192×40 batch 256 约 5-8ms）回发动作。Amdahl 上限取决于
   引擎份额，配合 1. 可达 5-10×。鸣牌/打断窗口的状态机是已知易错区（SKILLS 警告），
   需要引擎级单测护航。
3. 分两步验证：**scale-ladder 实验**（128×6 → 128×10 → 192×20，同协议同局数，看 Elo 与
   参数量的标度律和「每美元 Elo」），再决定是否冲 192×40。
4. 同步注意：更大模型可能需要更多 games_per_iter / 更低 lr / warmup（exp19 教训按比例设）。

## C. DQN vs REINFORCE/PPO——「有限状态」的误区与真正的差异点
先纠正前提：麻将是**动作空间小（272）、状态空间天文级**的任务，「有限」给不了表格法优势；
所有方法都在做函数逼近，比较的是**哪种目标更适合这个问题**。

DQN（Mortal 的选择）的真实优势：
1. **反事实估值**：Q(s,a) 对每个合法动作（含没选的）都给估计——推/折决策本质上是比较
   Q(push) 与 Q(fold)；策略梯度只对采样到的动作有信号。对防守学习这点可能关键。
2. **离策略复用**：经验回放可把每局用多次。我们的瓶颈正是对局生成（CPU rollout），
   而 PPO 的复用被信任域卡死（exp9：reuse44 倒退）。DQN 天生为回放设计。
3. **能吃别人的轨迹**：Mortal 选 DQN 首先是因为它从**人类牌谱离线学习**——这条优势对我们
   的纯自对弈路线不适用。

DQN 的劣势：多智能体自对弈下的非平稳性（回放里的对手已过时）、Q 过估计与目标网络调参、
策略是 argmax/ε-greedy 而非随机策略（麻将作为不完美信息博弈，最优策略本就可能是混合的）。

项目内证据指向「价值侧更重要」：GAE（更好的 V）是最大杠杆、exp11 证明 critic 能感知危险。
**结论：不整体切换，做单变量实验 exp24**：在共享协议上比较 PPO+GAE vs Double-dueling-DQN
（n-step、回放、动作掩码、目标网络），同局数预算；判据 Elo + defense_iq（反事实估值是否
兑现为防守）。折中候选：**Q-actor-critic**（保留随机策略，advantage = Q(s,a) − V(s)，
Q 头提供反事实），可作第三臂。全部纯自对弈，零知识注入。

## 优先级（等 exp20 M1/M2 后定）
exp23 输入 v3（最便宜、直指防守可学性）→ exp22 联赛 → 引擎优化 + GPU 批推理（scale 前置）
→ scale-ladder → exp24 DQN/Q-AC。
