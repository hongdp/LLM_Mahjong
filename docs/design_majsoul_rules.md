# 引擎规则向雀魂对齐（单局内规则）— 设计与记录

> 2026-08-23。用户指令：把容易改的"单局内"规则按雀魂改；多局结构（连庄/本场/供托跨局/半庄顺位）留作后续。

## 二、实施决策

### 赤宝牌表示
- 牌山里红五写作 `0m/0p/0s`（mjai `5mr` 的我方写法）。**手牌内部仍存 `5m`**（与所有 shanten/听牌/计数逻辑
  零改动），另记 `red_hand[pid][suit]∈{0,1}`；牌河/副露里的红五以 `0m` 记录（公开信息）。
- 动作：`discard tile="0m"` / `riichi tile="0m"` 与普通 5 并列为独立动作——打红五还是普通五是真实决策。
  合法性：`0m` 需 `red_hand>0`；`5m` 需 非红副本 >0。立直锁手摸到红五 → 只能摸切 `0m`。
- 副露用到 5 时自动优先用**非红**副本（与桥接"尽量留红五"一致，去掉一个边际决策）；杠四张必含红。
- 算分：`has_aka_dora=True`，136 索引用 `FIVE_RED_*`（16/52/88）标记红五，库自动计赤宝牌。
- 宝牌指示牌为红五时，指示 6（与普通 5 相同）。
- 编码器：新变体 `v1r` = v1 + 5 平面（自家红五；四家可见红五：牌河+副露，相对座位）；`v3r` 同理。
  旧变体 `v1/v3` 对红五折叠（老 checkpoint 作标尺不受影响）。
- 动作空间：`ACTION_DIM` 272 → **279**：+3 `discard 0x`、+3 `riichi 0x`、+1 `kyuushu`。
  老模型（头 272）走折叠模式：无普通 5 可打时 `0m` 映射到 5m 槽位；`kyuushu` 永不宣告。

### 其余规则
- 人和：`is_renhou=False`。双倍役满：`has_double_yakuman=True`。
- 杠宝牌：暗杠即翻；大明杠/加杠 → `pending_dora_reveal`，该家打出一张后翻（被抢杠则不翻）。
- 流局满贯：荒牌流局时，某家牌河全为幺九且**无一张被鸣**（`river_events.called` 全 False）→ 按满贯自摸结算
  （亲 4000 all / 子 2000·4000），替代听牌费；多家同时满足各自结算。
- 途中流局（结算：无听牌费；供托与单局流局同样留桌）：
  - 九种九牌：第一巡、无鸣牌、摸牌后手中幺九种类 ≥9 时提供 `kyuushu` 动作，宣告即流局；
  - 四风连打：前四张打牌为同一风且期间无鸣牌；
  - 四家立直：第四家立直宣言牌通过响应窗口后；
  - 四杠散了：≥2 家合计 4 杠后该杠者的打牌通过响应窗口后（一家 4 杠可继续）；
  - 三家和了：三家同时荣和 → 流局。
- 结果摘要新增 `途中流局(原因)`；`final_rewards` 同流局。

### 纪元
这是引擎纪元 3（纪元 2 = 精确立直暗杠 + 竞技场 A−B 指标）。合并后整池重校；历史 checkpoint 全部未见过赤宝牌，
作为标尺时在新规则下重新评分即可（规则对所有人相同）。训练侧：后续新 run 用 `v1r/v3r` + 279 动作头。
